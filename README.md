# AI FOOD SCANNER

เว็บไซต์โภชนาการภาษาไทย สไตล์ Modern Healthcare สำหรับคอมพิวเตอร์และมือถือ ใช้ HTML/CSS/JavaScript, Chart.js และ Backend Node.js CommonJS

## สถานะการส่งมอบ

- โหมดทดลอง ค้นหา คำนวณสารอาหาร กราฟ และประวัติ ใช้งานได้โดยไม่ต้องมี API Key
- โหมด AI จริงมี Backend adapter แล้ว แต่ **ยังไม่พร้อมวิเคราะห์ภาพจริงจนกว่าจะตั้งค่าและทดสอบกับ Vision gateway ที่ได้รับอนุญาต** ยังไม่มี endpoint หรือ credentials ให้ทดสอบในงานนี้
- โหมดทดลองระบุ DEMO ชัดเจน ผู้ใช้เลือกอาหารเอง ไม่ได้ตรวจจับอาหารในภาพ และไม่ใช่ผล AI
- ยังไม่ได้ยืนยันว่าเป็นโปรเจกต์ `legacy` หรือ `p01` จึงไม่ผูกพอร์ต deploy หรือฐานข้อมูลใด ใช้พอร์ตท้องถิ่นที่ระบบเลือกให้เท่านั้น
- ไม่มีฐานข้อมูลหรือบัญชีผู้ใช้ ประวัติเก็บเฉพาะเบราว์เซอร์ ไม่ซิงก์ข้ามอุปกรณ์
- ยังไม่ได้ Deploy และห้องนี้ไม่อนุญาตเผยแพร่ Public

## ไฟล์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `package.json` | dependencies และคำสั่งเริ่ม/ตรวจ/ทดสอบ |
| `server.js` | Backend, API, แปลงรูป, ตรวจข้อมูล และ self-test |
| `public/index.html` | หน้าหลัก วิเคราะห์ ประวัติ และเกี่ยวกับ |
| `public/style.css` | responsive design และ animation |
| `public/index.js` | upload, search, charts, history และ UI |
| `.env` | environment เฉพาะเครื่อง ห้าม commit |
| `.gitignore` | กัน `.env` และ `node_modules/` เข้า Git |

ใช้ `public/index.js` แทน `script.js` เพราะ policy อนุญาตชื่อไฟล์ application เฉพาะรายการข้างต้น ภาพประกอบหน้าแรกเป็น SVG ที่วาดใน HTML ไม่ใช่ผลวิเคราะห์ ภาพผู้ใช้ไม่ถูกบันทึกลงดิสก์เซิร์ฟเวอร์ หากเพิ่มไฟล์ภาพประกอบให้ใช้ `public/images/` ตาม policy; Backend ปัจจุบันเสิร์ฟเฉพาะเส้นทางที่ระบุไว้ ไม่เปิดทั้งโฟลเดอร์โดยอัตโนมัติ

## ติดตั้งทีละขั้นตอนบน Windows

1. ติดตั้ง Node.js 24 LTS (แนะนำ; ต้องมีอย่างน้อย Node.js 22 ที่รองรับ `process.loadEnvFile`) พร้อม npm แล้วเปิด VS Code ใหม่
2. เปิดโฟลเดอร์ `foodscan` ใน VS Code และเปิด Terminal โดยตรวจว่าตำแหน่งปัจจุบันเป็นโฟลเดอร์นี้
3. ติดตั้ง dependencies ด้วยคำสั่ง `npm.cmd install --ignore-scripts` บน PowerShell เพื่อไม่เรียก `npm.ps1` ที่อาจถูก execution policy บล็อก และไม่รัน lifecycle scripts ระหว่างติดตั้ง ไม่ต้องเปลี่ยน execution policy หรือใช้สิทธิ์ Administrator
4. ตรวจ `.env` ที่เตรียมไว้: `HOST=127.0.0.1`, `PORT=0`, `NODE_ENV=development` ส่วนค่า AI เว้นว่างได้ โหมดทดลองไม่ต้องใช้ secret
5. ตรวจ syntax ด้วย `npm.cmd run check` และทดสอบด้วย `npm.cmd test` ผลสำเร็จต้องขึ้น `PASS` โดยไม่มี error
6. เริ่มด้วย `npm.cmd start` หรือ `node server.js` สามารถใช้เมนู Terminal > Run Task > Run AI Food Scanner locally ใน VS Code ได้ด้วย
7. Terminal จะแสดง `AI FOOD SCANNER: http://127.0.0.1:...` เปิด URL นั้นในเบราว์เซอร์ ห้ามเปิด HTML ด้วย double-click หรือ Live Server เพราะต้องเรียก Backend ต้นทางเดียวกัน
8. หยุดด้วย Ctrl+C พอร์ต `0` หมายถึงเลือกพอร์ตว่างชั่วคราว ทุกครั้งที่เปิดใหม่ URL อาจเปลี่ยน ประวัติจะแยกตาม origin/พอร์ต หากต้องการ URL คงที่ให้กำหนดพอร์ตพัฒนาที่ว่างของเครื่องตนเองหลังตรวจสอบแล้ว ไม่ใช่เดาพอร์ต deploy ของโปรเจกต์

หาก `npm.cmd` ไม่อยู่ใน PATH ให้เปิด Terminal ใหม่หลังติดตั้ง Node หรือใช้ `node` เรียก `npm-cli.js` จากการติดตั้ง Node นั้นโดยตรง ห้ามแก้ปัญหาด้วยการปิดมาตรการความปลอดภัยของเครื่อง

Sharp ใช้ optional native binaries ตามระบบปฏิบัติการ จึงต้องอนุญาต optional dependencies และติดตั้งใหม่บนเครื่องปลายทาง ห้ามคัดลอก `node_modules` จาก Windows ไป Linux หากติดตั้งโดยไม่ใช้ scripts แล้วโหลด Sharp ไม่ได้ ให้ใช้แพลตฟอร์ม/สถาปัตยกรรมที่รองรับและตรวจ optional dependencies ก่อน ไม่เปิด lifecycle scripts เพื่อหลบนโยบาย

## ทดลองใช้งาน

1. กดเริ่มสแกน/วิเคราะห์อาหาร
2. เลือกรูป ลากไฟล์ลงพื้นที่อัปโหลด หรือกดเปิดกล้อง
3. ตรวจภาพตัวอย่าง เปลี่ยนหรือลบได้ รองรับ JPG/PNG/GIF/WebP ไม่เกิน 5 MiB และ 20 ล้านพิกเซล ไม่รับ HEIC ต้องแปลงเป็น JPG ก่อน
4. เลือก **โหมดทดลอง** เลือกอาหารอ้างอิง และระบุน้ำหนัก 1–2,000 กรัม
5. กดวิเคราะห์ จะเห็นป้าย DEMO การ์ดสารอาหาร 7 ชนิด และกราฟ 2 แบบ ไม่ได้ตรวจว่าในภาพเป็นอาหารอะไร
6. กดบันทึกมื้อนี้ แล้วเปิดประวัติเพื่อดูรายละเอียด ลบทีละรายการ หรือลบทั้งหมดโดยมีการยืนยัน
7. แท็บค้นหาอาหารใช้ได้โดยไม่มีรูป เลือกอาหาร ระบุน้ำหนัก แล้วกดคำนวณ ข้อมูลระบุเป็นข้อมูลอ้างอิง ไม่ใช่ AI
8. ปุ่มเริ่มใหม่/ล้างข้อมูลจะล้างรูปและผลปัจจุบัน ไม่ลบประวัติที่บันทึกแล้ว

ปุ่มกล้องใช้ file input แบบ `capture="environment"` มือถือที่รองรับจะเปิดกล้องหลังหรือเสนอเมนูถ่ายภาพตามระบบปฏิบัติการ บนคอมพิวเตอร์หรือเบราว์เซอร์ที่ไม่รองรับจะเปิดตัวเลือกไฟล์แทน ไม่ใช่ระบบ live webcam streaming ยังไม่ได้ทดสอบกับกล้องมือถือจริง

## เชื่อมต่อ AI จริงอย่างปลอดภัย

1. ยืนยันโปรเจกต์กับเจ้าของก่อน (`legacy` หรือ `p01`) และรับข้อมูล endpoint ที่ถูกต้องของโปรเจกต์นั้น ไม่เดาพอร์ต DB หรือ credentials จาก Dashboard ล่าสุด
2. รับ HTTPS chat-completions URL ที่รองรับภาพแบบ data URL, JSON response format, โมเดล `class-codex` และ `reasoning_effort: low` จากระบบที่ได้รับอนุญาต
3. กรอก `.env` เฉพาะเครื่อง: `VISION_API_URL` เป็น URL เต็มของ endpoint; `VISION_API_KEY` เป็น key จริง; `VISION_MODEL=class-codex`; `VISION_REASONING=low`; `APP_ACCESS_TOKEN` เป็นรหัสส่วนตัวที่คาดเดายากอย่างน้อย 24 ตัวอักษร
4. เจ้าของพิมพ์ secrets ลง `.env` โดยตรง ไม่ส่งผ่านแชต ไม่ใส่ใน HTML/JavaScript frontend เอกสาร หรือ Git และอย่าใช้ API Key เป็นรหัสหน้าเว็บ
5. เริ่ม Backend ใหม่หลังแก้ environment ค่า environment ที่มีอยู่แล้วมีลำดับเหนือค่าในไฟล์ `.env`
6. เลือกโหมด AI จริง ใส่ **APP_ACCESS_TOKEN** ในช่องรหัสเข้าใช้ และยินยอมส่งภาพก่อนกดวิเคราะห์ รหัสไม่เก็บใน localStorage และล้างช่องเมื่อส่งคำขอ
7. ทดสอบด้วยภาพอาหารจริง/ภาพไม่ใช่อาหาร และตรวจผลกับฉลากหรือน้ำหนักที่ทราบก่อนใช้งานจริง ป้าย “ตั้งค่าแล้ว” หมายถึงมีค่า environment เท่านั้น ไม่ได้ยืนยันว่า gateway เชื่อมต่อสำเร็จ

Adapter ส่ง `POST` พร้อม bearer API key, `model`, `reasoning_effort`, `max_tokens`, `response_format` และ `messages` ที่มี `image_url` แบบ base64 คาดหวังคำตอบ `choices[0].message.content` ที่เป็น JSON ของอาหาร ส่วนประกอบ น้ำหนัก ความมั่นใจ สารอาหาร และข้อจำกัด ผู้ให้บริการที่ใช้ protocol อื่นต้องปรับ adapter ใน `server.js` ก่อน ไม่สามารถใช้ key อย่างเดียวโดยไม่มี endpoint ที่เข้ากันได้

Endpoint ต้องเป็น HTTPS ไม่มี username/password/query/fragment และไม่ตาม redirect คำขอหมดเวลา 45 วินาที คำตอบจำกัด 64 KiB Backend ตรวจชนิด/ช่วงค่าก่อนคืนผล หากยังไม่มี AI ระบบคืนข้อผิดพลาดชัดเจน **ไม่แทนด้วยผลจำลองอัตโนมัติ**

หน้าเว็บไม่เคยได้รับ provider API Key แต่รหัสเข้าใช้แอปต้องส่งจากเบราว์เซอร์ไป Backend จึงต้องใช้ HTTPS สำหรับการเข้าถึงผ่านเครือข่าย; HTTP ที่เตรียมไว้ใช้เฉพาะ loopback พัฒนาในเครื่อง ห้ามเปิดพอร์ตนี้สู่ Internet โดยตรง

## โภชนาการและกราฟ

- ข้อมูลอ้างอิง 8 รายการเป็นค่าประมาณของอาหารทั่วไปต่อ 100 กรัม โดยอ้างอิงแนวทางข้อมูล USDA FoodData Central ไม่ใช่ฐานข้อมูลสูตรอาหารไทยฉบับสมบูรณ์หรือการค้น USDA API สด ตรวจแหล่งข้อมูลที่ https://fdc.nal.usda.gov/ ก่อนนำไปใช้เชิงวิชาการ
- คำนวณปริมาณด้วยค่าต่อ 100 กรัมคูณน้ำหนัก/100
- พลังงานใช้ kcal; โปรตีน คาร์บ ไขมัน น้ำตาล ใยอาหารใช้กรัม; โซเดียมใช้มิลลิกรัม
- กราฟ doughnut แสดงสัดส่วนพลังงานจากโปรตีน/คาร์บ/ไขมันด้วย 4/4/9 kcal ต่อกรัม ไม่ใช่สัดส่วนจากน้ำหนัก และอาจไม่ตรงแคลอรีรวมทุกองค์ประกอบ
- กราฟแท่งเปรียบเทียบเฉพาะหน่วยกรัม ไม่รวมโซเดียมหน่วย mg และไม่ใช่ร้อยละความต้องการรายวัน
- น้ำมัน เครื่องปรุง และน้ำหนักจริงสรุปจากรูปไม่ได้แน่นอน ผลไม่ใช้วินิจฉัยโรค กำหนดอาหารรักษาโรค หรือคำนวณยา คะแนนความมั่นใจเป็นค่าที่ AI รายงานเอง

## ความเป็นส่วนตัวและข้อจำกัด

- Backend ตรวจชนิดภาพที่ decode ได้จริงและแปลง JPEG ใหม่ ลบ metadata/EXIF ปรับด้านยาวไม่เกิน 1,280px และใช้เฟรมแรกของภาพเคลื่อนไหวก่อนส่งผู้ให้บริการ
- ภาพอยู่ในหน่วยความจำระหว่างประมวลผล ไม่เขียนไฟล์หรือ DB แต่ผู้ให้บริการ AI อาจเก็บข้อมูลตามนโยบายตนเอง ต้องอ่านก่อนใช้ หลีกเลี่ยงใบหน้าและข้อมูลส่วนตัวในภาพ
- กดบันทึกจึงเก็บรูปย่อและผลใน localStorage สูงสุด 30 รายการ ตัดรายการเกิน 365 วันเมื่อโหลด/เข้าประวัติ ไม่ใช่งานลบตามเวลาบนเซิร์ฟเวอร์ ล้างข้อมูลเบราว์เซอร์/เปลี่ยนอุปกรณ์/เปลี่ยนพอร์ตแล้วอาจไม่พบประวัติเดิม
- storage เต็มหรือถูกบล็อกจะแจ้งเตือน; ไม่อ้างว่าบันทึกสำเร็จ และประวัติในเครื่องที่ใช้ร่วมกันไม่ใช่พื้นที่ส่วนตัวที่มีการเข้ารหัส
- ฟอนต์เรียก Google Fonts จึงมีคำขอไปผู้ให้บริการฟอนต์ หากอินเทอร์เน็ตขาดยังใช้ฟอนต์สำรองได้ Chart.js เสิร์ฟจาก dependencies ในเครื่อง ไม่ใช้ CDN
- จำกัดคำขอวิเคราะห์ 12 ครั้ง/นาที/IP และประมวลผลภาพครั้งละ 1 คำขอต่อ process; ตอบ 429 เมื่อเต็ม Rate limit อยู่ในหน่วยความจำและรีเซ็ตเมื่อ restart ไม่ใช่ระบบบัญชี/โควตาแบบหลายเครื่อง
- ไม่ได้วัด peak RAM ภายใต้โหลดจริง ต้องทดสอบกับเพดาน 192 MiB บน runtime เป้าหมายก่อน Deploy

## ตรวจสอบและแก้ปัญหา

- `npm.cmd run check`: ตรวจ syntax ทั้ง Backend และ frontend
- `npm.cmd test`: ทดสอบ HTTP 15 กรณี รวม static/chart asset, ปิดเส้นทาง secret/traversal, demo, JSON ผิดรูปแบบ, cross-origin, โภชนาการ, การลบ metadata รวมกับ unit checks ของ AI schema และ MIME ปลอม โดยไม่เรียก AI ภายนอก
- `npm.cmd audit --omit=dev`: ตรวจ dependencies กับฐานข้อมูล npm; ผลล่าสุดระหว่างพัฒนาไม่พบช่องโหว่หลังอัปเดต Sharp เป็น 0.35.5 ไม่ใช่การรับรองจาก scanner ของ platform
- หากโหลดหน้าไม่ได้ ให้ตรวจ URL จริงที่ Terminal แสดงและว่า server ยังทำงานอยู่
- หากไม่มีกราฟ ให้ติดตั้ง dependencies แล้วเปิด `/vendor/chart.js` ผ่าน server ตรวจว่าไม่เป็น 404
- 400/413: ตรวจรูป ชนิดไฟล์ ขนาด ความละเอียด และน้ำหนัก
- 401: รหัสเข้าใช้แอปไม่ถูกต้อง; 403: origin ไม่ตรงกับ server
- 429: รอหนึ่งนาทีหรือรอคำขออื่นเสร็จ; 502/504: gateway/format/timeout; 503: ยังตั้งค่า AI ไม่ครบ
- ห้ามแสดง API Key, รหัสเข้าใช้ หรือ `.env` ในภาพหน้าจอ/log ที่เผยแพร่

## ก่อน Deploy ตาม policy ห้อง

1. ยืนยันโปรเจกต์และพอร์ตที่ระบบจัดสรรจริงก่อน ยังไม่มีการเชื่อม DB จึงไม่ต้องตั้ง DB vars หรือรัน SQL ใด ๆ
2. ตั้ง managed environment ผ่านระบบด้วย `PORT`, `HOST` ที่ runtime กำหนด, `NODE_ENV=production` และค่า AI ของโปรเจกต์นั้น ห้ามนำ loopback/พอร์ต 0 ของเครื่องพัฒนาไปแทนค่าบนเซิร์ฟเวอร์ และห้ามส่ง `.env` เป็น source artifact
3. ส่ง executable source เฉพาะ `package.json`, `server.js`, `public/index.html`, `public/style.css`, `public/index.js` ตาม allowlist; ใช้ `.gitignore` ที่ให้ไว้ ไม่แนบ `node_modules/`, `.vscode/` หรือ `.env` เอกสารนี้ไม่ใช่ executable source
4. `package-lock.json` เป็น lockfile ที่ npm สร้างสำหรับเครื่องพัฒนา หากระบบ enforce รายชื่อ artifact อย่างเคร่งครัด อย่าแนบไฟล์นี้ใน source upload/Git Deploy ที่ระบบรับเพียง 5 ไฟล์ ให้ตรวจนโยบาย artifact ของ platform ก่อน; บนเครื่องพัฒนาสามารถเก็บ lockfile สำหรับติดตั้งซ้ำได้ Dependencies หลักตรึงเวอร์ชันไว้ใน `package.json`
5. ติดตั้งโดยไม่รัน lifecycle scripts ใน isolated non-root runtime ที่จำกัดทรัพยากร ตั้ง HTTPS/routing และตรวจความปลอดภัยของ secret/isolation อีกครั้งก่อนเปิด route
6. **ตรวจ Backend ซ้ำก่อน Deploy** และผ่าน Semgrep, OSV, Gitleaks โดยไม่มี high finding ที่บล็อก ผลต้องใหม่ไม่เกิน 24 ชั่วโมงตาม policy ห้อง; เครื่องนี้ยังไม่ได้รัน scanners ทั้งสามและห้ามถือ npm audit แทนผลสแกนเหล่านั้น
7. ยังไม่เปิด Public เนื่องจาก publication ของห้องปิดอยู่ ไม่ข้าม approval หรือ safety floor แม้เว็บทำงานในเครื่องได้
8. หากเพิ่ม DB ภายหลังต้องยืนยัน database.name/user/host ของโปรเจกต์ก่อน ตรวจ `SELECT DATABASE()` ก่อน SQL และส่ง migrations ผ่านหน้าฐานข้อมูลเท่านั้น ห้ามรัน migration เมื่อเริ่มแอปหรือจาก npm/Git
